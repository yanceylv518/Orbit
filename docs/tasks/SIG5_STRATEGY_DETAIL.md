> 前置：SIG-3、SIG-3b、SIG-4 均已验收并上线。
> **视觉基准：`docs/design/STRATEGY_DETAIL_MOCKUP.html`（三个标签页：信号策略 / 自动策略 / 故障与空态）。有歧义时以样稿为准。**

## 1. 为什么

**病根不是排版，是这一页几乎没连后端。**

`frontend/src/pages/StrategyCenterPage.vue` 第 79–84 行的 `definitions` 对象，把四个策略的全部描述、指标、参数、过滤条件写死成前端字符串，与真正在跑的规则零连接。实际后果：

| 现状 | 后果 |
|---|---|
| 第 03 节「参数取什么值」对三个信号策略只写「由用户在信号配置面板设置」「以当前配置为准」 | 用户问参数取什么值，页面回答"以当前配置为准"，等于没回答。而后端 `operations.configuration` 里 SIG-3b 的 20 项真实值、人话标签、允许范围全都在，一个都没用 |
| SIG-3 改了规则，页面文案一字未动 | 页面描述的是旧规则；高位回调的三层保护完全没提 |
| 趋势策略参数是前端手抄常量 | **违反 UI-R2 已立的纪律**：策略中心冻结参数须来自后端接口，全前端 grep 无参数常量副本 |
| 权益曲线与持仓图只取趋势数据 | 三个信号策略页面顶部两个大区**永远是空的**（"等待第一笔权益观测""当前没有持仓"） |
| 状态徽章只读开关位置 | 扫描进程死了页面照样绿。2026-08-17 已实际发生：账本 manifest 拒绝启动，进程崩溃，页面显示「提醒已启用」 |

## 2. 参数归位（用户 2026-08-17 决定）

**原则：参数是策略的定义，长在策略身上。**

用户的实际用法是盯住一个形态反复做减法；让人离开该策略页、去另一个页面的混合面板里找旋钮，正好打断这个循环。

### 2.1 归属判据

| 这项参数影响什么 | 归到哪 |
|---|---|
| 只影响这一个策略的信号内容 | **该策略详情页**，可改 |
| 影响多个策略的信号内容 | **每个相关策略详情页都可改**，带「共用」标记并写明影响范围 |
| 只影响投递（推不推、推给谁、推几条） | **信号页**运行设置区 |

### 2.2 20 项的具体归位

- **共用（三个信号策略页均可改，带标记）**：可交易性门槛、成交额回看天数、每日处理上限
- **放量突破专属**：突破通道长度、最低放量倍数
- **高位回调专属**：最低急跌幅度、急跌观察长度、允许的长周期状态、崩塌判断窗口、崩塌回撤上限、急跌起点高位窗口、急跌起点回撤上限
- **持续强势专属**：趋势强度分位、近期量能窗口、基准量能窗口、最低持续量比、价格高位窗口、距高点比例上限
- **同币种冷却小时**：按其当前实际所属信号族归位；若实现为全局，则按共用处理并标记
- **留在信号页**：每日推送上限、推送渠道与凭证、服务总开关、账户绑定

**共用参数在任一策略页保存后，另外两页立即同步显示新值；保存前必须提示影响范围。**

### 2.3 信号页的参数面板整体移除

不是折叠、不是收起——**移除**。信号页只保留：服务总开关、推送渠道与凭证、账户绑定、健康与告警、每日信号列表与人工留痕。

### 2.4 回放入口跟随参数

按族回放与改动预览入口进入策略详情页（"改完先回放看差异"）。信号页保留跨族的全量回放。

## 3. 详情页结构（两类策略统一骨架）

顺序即优先级：**先回答"它替我干了什么"，再回答"它是什么"。**

| 区块 | 信号策略 | 自动策略 |
|---|---|---|
| 顶部状态 | 真实扫描状态 + 最近扫描时刻 + 启停 | 真实执行状态 + 最近/下次调仓 + 停止 |
| 01 它替我干了什么 | 近 30 天推送数、已了结、模拟账累计 R、赚亏比 + 累计 R 曲线 | 策略与实际账户双曲线 + 累计、回撤、前向进度 |
| 02 样子 | **最近若干个信号的价格缩略图**（信号点 + 止损位 + 结果） | 当前持仓表（方向、权重、条形、一句话理由） |
| 03 它按什么规则做 | **真实生效参数，就地可改**，按人话分组，共用项带标记 | 冻结参数**只读**，标注冻结指纹 |
| 04 什么时候它不动作 | 排除条件逐条摊开；**「超每日上限」须写明是入账不推送，不是丢弃** | 已知弱点逐条列出 |
| 05 刚才那一轮做了什么 | 本轮真实数字：币池数 → 初步命中 → 通过筛选 → 记账/推送 | （可选）最近一次调仓的目标差额 |
| 技术详情（折叠） | 进程状态、最近扫描与最近失败、规则指纹、配置修订号、**账本代次** | 冻结指纹、定义哈希、前向起点与周期数、实盘协议 |

**02 区块是关键**：认一个策略最快的办法是看它挑出来的图。这是用户反复强调的"图是让用户认得出策略的主要手段"。

## 4. 后端必须补的两项

### 4.1 按信号族的滚动模拟账成绩（硬前置）

现有 `_review` 按天、按决策分组，**不按族**；`rolling_30d_by_family` 只有条数，没有成绩。

新增按族读模型，至少含：近 30 天信号数、已了结数、进行中数、模拟账累计 R、赚/亏笔数、用于画累计 R 曲线的时间序列。**没有它，01 区块只能显示空态——不得用任何估算或占位数字填充。**

### 4.2 每族多个近期样本

`recent_samples_by_family` 当前每族只留 1 条（`desk.py:429`）。改为每族保留若干条（建议 6），含 `chart_before`/`chart_after` 与模拟结果。

### 4.3 趋势策略名称含内部代号

`strategy_catalog.py:87` 的 `name="TB4 多周期趋势篮子"` 含内部代号。**后端提供对用户的显示名，UI 不得出现 TB4 等内部标识**（沿用既有零代号红线）。前端现在是靠硬编码绕开这个问题的，搬迁后必须由后端给出干净名称。

## 5. 状态必须说真话

1. 信号策略状态取后端 `operations.service.running` 与 `market_data_fresh`，而非 `service.enabled`；三态区分：**扫描正常运行 / 已启用但超过 30 分钟没有成功扫描 / 已停用**。
2. 趋势策略状态须含新鲜度判断，不得仅凭「账本已初始化」显示运行中。
3. **数据取不到时默认值不得为"已启用"**。`StrategyCenterPage.vue:75` 与 `StrategyPage.vue:26` 现在都是 `|| { enabled:true }`——服务未部署反而显示绿灯，这是最坏的一种错。缺数据时显示「未部署 / 状态未知」。
4. 副标题不得写死"扫描服务正常运行"（`StrategyPage.vue:27`），必须反映真实健康。

## 6. 明确不在本卡范围

自定义筛选条件构建器、研究页重建、账本换代机制与启动失败告警（另行立卡）。
