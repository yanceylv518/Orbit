# 任务卡 SIG-6 v1：扫描取数改增量 + 限频与诚实报错

> 本卡自足。状态：待实现 ｜ 日期：2026-08-17 ｜ 交付：Codex ｜ 验收：Claude
> 触发：生产 Pushover 每 15 分钟推一条「扫描失败：RuntimeError」。

## 1. 病因（设计欠账，非偶发故障）

SIG-3 把币池从「3 日成交额中位数 ≥2 亿」放宽为「30 日中位数 ≥200 万」，池子从几十个放大到几百个，**但取数方式没有同步改**。

`backend/tools/run_sig1_signal_service.py:_market_window` 每一轮、每一个币都重新拉取：

```python
self.feed.closed_klines(symbol, "15m", 1440)   # 15 天历史
self.feed.closed_klines(symbol, "4h", 361)     # 60 天历史
```

**15 分钟里只新增 1 根 K 线，却把 1440 根全部重取一遍。**

| | 数值 |
|---|---|
| 单币每轮请求 | 2 次，其中 15m 请求 limit>1000（币安最高权重档） |
| 单币每轮权重 | 约 12 |
| 币安 USDT-M 合约 IP 限额 | 约 2400 权重/分钟 |
| 不触发限频的池子上限 | **约 200 个市场** |

超限后先 429、再升级为 418 封禁，于是**整轮取数全灭**。而单币异常被 `except Exception: continue` 静默吞掉，只在「成功取到窗口的市场 < 最低数量」时抛出一条笼统的
`RuntimeError("Binance 15m market data is unavailable for the minimum eligible universe")`——**报错信息完全指不出真实原因**。

## 2. 要做什么

### 2.1 K 线增量缓存（根治，优先级最高）

进程内按 `symbol × interval` 缓存已收盘 K 线：

- **首次**按当前长度拉满（15m 1440 根、4h 361 根）；
- **之后每轮只拉增量**——15m 取最近若干根（`limit` 落在最低权重档）并按 `close_time_ms` 去重合并；4h **只在 4h 边界后才更新**，其余轮次直接复用；
- 检测到缺口（新数据与缓存不连续）时，只对该币回补，不影响其他币；
- 缓存有上限并按最大所需历史裁剪，避免无限增长。

**目标：单币每轮权重从约 12 降到 2 以内**，同等池子规模下请求量下降一个数量级。

### 2.2 全局限频与退避

- 令牌桶控制每分钟总权重，留出余量（不占满限额，须与趋势策略共享同一 IP）；
- 尊重 429/418 的 `Retry-After`，指数退避；被封禁期间**跳过本轮并如实记录**，不重试加剧封禁；
- 并发数与权重预算可配置。

### 2.3 报错必须说人话且分类

- 统计本轮各类失败原因（限频 / 超时 / HTTP 错误 / 数据不足），写入扫描记录；
- 告警与推送文案改为具体原因，例如「218 个市场中 214 个取数失败，主因 HTTP 429 限频」，**不得只报异常类名**；
- **推送去重**：同一失败原因连续出现时不得每 15 分钟推一条。首次推送，之后按退避间隔（如 1 小时）提醒一次，恢复时推一条恢复通知。

### 2.4 币池规模上限

新增可配置的「最多跟踪市场数」（默认建议 300），超出时按 30 日成交额中位数由高到低截断，**并在页面明确显示「因上限截断了 N 个市场」**，不得静默丢弃。

## 3. 红线

- 不得为降低请求量而缩短检测所需历史（`collapse_lookback_days` 等由用户配置决定，取数须满足配置，而不是反过来）；
- 缓存只存**已收盘**K 线；任何情况下不得把未收盘数据喂给检测函数；
- 趋势策略与信号服务共用同一 IP 配额，限频预算必须为趋势策略留出余量，**不得让信号扫描饿死趋势前向**。

## 4. 验收清单

1. 增量缓存生效：第二轮起单币请求量与权重显著下降（专测：以假 feed 断言第二轮的 `limit` 与调用次数）；
2. 4h 数据在非 4h 边界的轮次不重新拉取（专测）；
3. 缓存缺口能被检测并只回补该币（专测）；
4. 限频器在超预算时排队而非直接失败；429/418 触发退避且不重试（专测，故障注入）；
5. 失败原因分类统计并出现在扫描记录与告警文案中（专测：断言文案含市场数与主因，不含裸异常类名）；
6. 同一失败原因不得每轮推送；恢复时推送恢复通知（专测）；
7. 市场数上限可配置，截断数量在页面可见（专测）；
8. 缓存只含已收盘 K 线（专测）；
9. 全量测试绿 + `verify_modular_baseline.py` 通过 + TB4 零触碰。

## 5. 临时缓解（已告知用户，不替代本卡）

在信号策略页把「可交易性门槛」从 200 万调高到 5000 万–1 亿，缩小币池即可恢复扫描。**代价是重新漏掉小市值启动币**——正是 SIG-3 要解决的问题，因此本卡完成后应把门槛调回。
