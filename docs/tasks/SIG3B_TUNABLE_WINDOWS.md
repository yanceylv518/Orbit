# 任务卡 SIG-3b v1：窗口参数拆分 + 信号参数配置面板

> 本卡自足。状态：待实现 ｜ 日期：2026-08-17 ｜ 交付：Codex ｜ 验收：Claude
> 前置：SIG-3 已验收（`e02dc28`）

## 1. 为什么

两个问题一起解决：

**问题一：三处用途共用同一个 14 天窗口，但它们判断的是不同的事。**

| 用途 | 判断什么 | 合适的窗口 |
|---|---|---|
| 从高位摔下来（`maximum_start_drawdown_from_high`） | **这次急跌的起点在哪** | 短（贴近交易周期） |
| 崩塌熔断（`maximum_drawdown_from_high`） | **这个币是不是在中期崩塌** | 长（需要远视角） |
| 持续强势要求价格在高点附近 | **是不是真的强势** | 长（创两周新高才算强势） |

**实测依据（TUT 真实数据，原始触发 56 次，起点阈值 15%）**：

| 高点窗口 | 剩余信号 |
|---|---|
| 1 天 | **7 个漏网** |
| 2 天 | 0 |
| 3 / 5 / 7 / 10 天 | 0 |

**2 天以上效果完全相同**——14 天里有 12 天是白搭的。且长窗口有副作用：**暴涨过的币会被长期误封**（如某币涨 192% 后正常回调 30%，用 14 天窗口会被崩塌熔断挡住两周，而暴涨后的回调不等于崩塌）。

**问题二：这些值改不了。** 它们虽在配置文件里，但只能由开发者改服务器文件，用户无法在界面调整——与「参数由用户自己配」的既定方向冲突。

## 2. 要做什么

### 2.1 拆成三个独立配置项

| 新键 | 用途 | 初始值 |
|---|---|---|
| `pullback_start_high_lookback_days` | 从高位摔下来 · 高点窗口 | **3** |
| `collapse_lookback_days` | 崩塌熔断 · 高点窗口 | 14（不变） |
| `high_lookback_days` | 持续强势 · 高点窗口 | 14（不变） |

对应阈值（`maximum_start_drawdown_from_high` 0.15、`maximum_drawdown_from_high` 0.30、`maximum_distance_from_high` 0.03）保持独立，不得互相复用。

### 2.2 信号参数配置面板（最小可用版）

在信号页新增配置区，**管理员可直接编辑并保存**下列参数，保存即生效：

- **币池**：可交易性门槛（金额）、回看天数
- **突破**：通道长度、放量倍数
- **高位回调**：跌幅门槛、跌幅观察窗、长周期状态要求、崩塌熔断（窗口 + 阈值）、从高位摔下来（窗口 + 阈值）
- **持续强势**：趋势强度分位、量比与其窗口、距高点比例与窗口、冷却小时数
- **通用**：每日限额、推送条数上限、三类信号开关（含停用原因）

每项须有：**人话标签 + 一句话说明 + 当前值 + 允许范围**。非法值给出清晰报错，不静默接受。

### 2.3 变更留痕

每次保存写入只追加的配置账本：时间、操作者、改了哪些项、旧值→新值、可选备注。信号模拟账的范围版本号随之递增（沿用 SIG-3 已有机制）。

## 3. 明确不在本卡范围

- 自定义筛选条件构建器（字段 + 比较符 + 与或组合）——后续任务卡；
- 规则回放预览与改动前后并排对比——后续任务卡（本卡先让参数可改，回放随后补上）。

## 4. 验收清单

1. 三个窗口为独立配置键，互不复用（专测：改其一不影响其二）；
2. `pullback_start_high_lookback_days` 初始为 3，且以 TUT 真实历史回放验证高位回调信号数仍为 **0**；
3. 配置面板可编辑上列全部参数，保存即生效，页面显示当前生效值；
4. 非法值（越界、非数字、窗口为 0）被拒绝并给出人话报错（专测）；
5. 配置变更写入只追加账本，含旧值→新值（专测）；
6. 停用某类信号仍须填原因（沿用 SIG-3）；
7. 界面零内部代号、文案人话；
8. 全量测试绿 + `verify_modular_baseline.py` 通过 + TB4 零触碰。
