## 5. 两个会影响体验的落地细节

### 5.1 信号扫描是**独立进程**，必须一起重启

新规则写在 `config/signals/sig1.v1.json`，由 `backend/tools/run_sig1_signal_service.py` **在启动时读一次**。只重启后端 API 不够——**扫描进程不重启，新规则不生效**。

好消息：网页上改的 20 项参数走的是控制账本，扫描进程每 15 分钟循环重读并在版本号变化时重置币池缓存，**日常调参不需要重启**。

### 5.1b 改了 `sig1.v1.json` 就必须先归档旧账本（2026-08-17 实际踩到）

**现象**：上线后信号归零，但策略页照样绿着「提醒已启用」。

**病灶**：信号账本 manifest 里存着 `spec_sha256 = sha256(sig1.v1.json)`。`signal_ledger.py:41` 在哈希不符时抛
`RuntimeError("SIG-1 immutable manifest differs from requested configuration")`——**这一步在 `while True` 之前，`--loop` 的异常兜底够不着，进程启动即死**，界面上没有任何提示。

**这个校验不能放宽**：它保证账本每条记录都能对应到产生它的那套规则，是信号模拟账全部评估价值的根基。

**因此规则改动分两类，路径不同：**

| 改动 | 路径 | 是否换代 |
|---|---|---|
| 面板上调 20 项参数 | 控制账本 `configuration_values` + `scope_version` 递增 | 否，下一轮扫描自动生效 |
| 改 `sig1.v1.json`（含新增信号族） | 直接改文件 | **是，旧账本必须先归档** |

**操作**：`mv var/signals/sig1 var/signals/sig1.gen<N>-<日期>`，重启扫描进程自动建新 manifest。
**两项已知代价**：① 归档代在页面上不可见（信号台只读一个目录），需多代读取才能找回；② 旧代里未平的模拟单永久悬停、不再有结果，应标注「因规则换代中断」而非无声消失。

### 5.2 回放需要历史数据仓，服务器上按记录没有

`SignalReplayService` 读 `var/calibration/shortline-data-v1`（本机 3.3 G）。生产未安装 DATA-1R，回放会诚实返回「数据不足」而非假装有结果。

**解决**：上线后在「数据」页点更新历史数据，在服务器上构建（内置磁盘余量守卫，要求 ≥15 GB 空闲）。在构建完成前，SIG-3/3b 的规则修正与参数面板照常工作，只有回放不可用。
