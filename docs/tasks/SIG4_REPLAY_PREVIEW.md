# 任务卡 SIG-4 v1：规则回放与改动预览

> 本卡自足。状态：待实现 ｜ 日期：2026-08-17 ｜ 交付：Codex ｜ 验收：Claude
> 前置：SIG-3（信号范围修正）、SIG-3b（20 项参数可配）均已验收。

## 1. 为什么

参数现在可以改了，**但改完看不到效果**——只能保存后干等它推信号，等于蒙着眼睛调。这是「黑盒」问题的最后一块：**用户无法在信号推出来之前，知道这套规则会给他什么。**

回放要解决的正是这件事：**改完立刻看到「过去这段时间按新设置会推什么」，先看后定，不必上线试错。**

## 2. 三个功能

### 2.1 规则回放

- 选时间段（默认**过去 7 天**，可选 30 天），**按当前生效配置**在历史数据上完整跑一遍；
- 输出该期间会产生的**全部信号**，逐条显示：币种、类型、时刻、触发原因、参考进场/止损/1R·2R·3R；
- 每条带**图**（价格线 + 均线 + 成交量 + 信号点 + 止损位，沿用信号台图形语言）；
- 每条带**事后结果**：最大浮盈、最大浮亏、若按机械规则执行的收益；
- **被每日限额截断的信号单独标出**，不隐藏。

### 2.2 改动预览（核心）

- 在配置面板改任一参数后，**不保存也能预览**：立刻用「改后的设置」重跑同一时间段；
- **并排对比**：改前 vs 改后
  - 信号总数变化（按类型分列）
  - **新增了哪些信号**（改后才有的）
  - **消失了哪些信号**（改前有、改后没了）
  - 币种构成变化
- 用户看完再决定**保存或放弃**。

### 2.3 数据来源与一致性

- 回放必须使用**与实时扫描完全相同的检测函数**（`detect_sig1_signals`），不得另写一份回放逻辑；
- 历史数据取服务器上的数据仓；数据不足时如实说明缺口，不静默截断。

## 3. 纪律红线（必须写进页面）

**回放用于理解规则行为，不得用于挑选收益最好的参数。**

- **不提供**参数收益排行榜、「最优参数」推荐、按历史收益排序的参数组合；
- 回放结果页固定标注：**「历史回放不预测未来。规则变更的真实效果，由信号模拟账在未来数据上裁决。」**
- 理由：在同一段历史上反复试参数直到好看，就是过拟合——这正是本项目整套研究纪律所防范的。**回放的正当用途是「看清楚这套规则会给我什么」，不是「找出赚最多的那组数」。**

## 4. 不在本卡范围

自定义筛选条件构建器（字段 + 比较符 + 与或组合）、研究页与策略页重做——后续任务卡。

## 5. 验收清单

1. **回放与实时同源**：同一段历史、同一配置下，回放输出与实时扫描逐条一致（专测）；
2. 回放结果含逐条图与事后结果，被限额截断项单独标出；
3. 改动预览可在**不保存**的前提下运行，并给出改前/改后并排差异（新增、消失、总数、币种构成）（专测）；
4. **无收益排行榜、无最优参数推荐、无按收益排序**（模板断言）；
5. 纪律标注文案在结果页固定可见；
6. 数据不足时如实提示，不静默截断（专测）；
7. 界面零内部代号、文案人话；
8. 全量测试绿 + `verify_modular_baseline.py` 通过 + TB4 零触碰；
9. 桌面与 390×844 实测。
