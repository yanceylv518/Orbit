# 小资金实盘协议（LIVE-SMALL V3）

状态：**已冻结（2026-07-31，500 USDT，3 倍目标风险，逐仓 3x）**
适用对象：TB-R 冻结多周期集成趋势篮子（信号与 `TB4_SPEC` 完全一致）

> **V3 修订（2026-07-31，用户决定）**：保留 TB4 原始纸面基准和全部信号参数不变，实盘目标
> 权重统一按 TB4 权重乘以 `3.0`；12 个 USDT 永续市场统一使用逐仓保证金、初始杠杆 3x，并
> 关闭自动追加保证金。该修订会实质放大盈亏，不是单纯修改交易所显示杠杆。任何 V1/V2
> 自动执行授权在升级时失效，必须重新准备账户、预检并使用 V3 确认短语授权。

## 0. 定位与授权范围

- 本协议授权系统用预先冻结的 **500 USDT**，自动执行 LIVE-SMALL V3 冻结清单。
- 信号来源仍是原始 TB4；LIVE-SMALL 只在目标仓位投影层应用固定 `3.0` 倍数，不向研究策略
  增加可调参数。
- TB4 paper 继续按原始 1 倍风险独立运行；实盘和 paper 使用两本账，不能把两条权益曲线的
  差直接解释为滑点。
- 自动执行的唯一指令源是 V3 冻结清单。清单之外的订单、旧版清单或风险配置回读不一致都
  必须 fail closed。

## 1. 冻结风险配置

| 项 | V3 冻结值 |
|---|---:|
| 实盘资金基准 | 500 USDT |
| TB4 原始目标波动 | 年化 10% |
| 实盘目标权重 | `TB4 target_weight × 3.0` |
| 实盘目标波动（模型口径） | 约年化 30%，不是收益或损失保证 |
| 实盘 gross cap | TB4 原始 gross cap `1.0 × 3.0`，即最多约 3 倍资金名义敞口 |
| Binance 初始杠杆 | 3x |
| 保证金模式 | 12 市场全部 `ISOLATED`（逐仓） |
| 自动追加保证金 | 关闭 |
| 持仓模式 | 单向持仓 |

逐仓只隔离单个合约分配到的保证金，不能消除组合亏损、跳空、滑点、Funding、强平或多个逐仓
仓位同时亏损的风险。交易所的 3x 杠杆设置决定保证金/强平参数；目标仓位乘 3 才是风险真正
增加的来源，两者缺一不可。

500 USDT 仍可能不足以表达所有 12 个市场。低于交易所最小名义金额的目标保持空仓并在清单中
标记，复盘时作为结构性跟踪误差单列。

## 2. 自动执行与逐轮闸门

1. 每次再平衡由同一份 TB4 冻结信号同时生成：
   - TB4 原始目标；
   - 乘以 3 的 LIVE-SMALL V3 目标；
   - 按交易所步长和最低名义金额取整后的可执行目标。
2. 下单前同步真实账户，并按真实持仓计算调仓差额，不使用“上次计划仓位”代替账户事实。
3. 每一轮发送任何订单前，重新回读 12 市场配置，要求全部为：
   - `leverage = 3`；
   - `marginType = ISOLATED`；
   - `isAutoAddMargin = false`。
4. 任一市场配置不符、账户快照过期、规则过期、账本异常或清单协议不是 V3，整轮拒绝下单。
5. 同一 epoch / 再平衡时点最多执行一次；失败不自动追单；急停后该 epoch 永久锁定。
6. 执行后记录订单意图、成交、手续费、滑点和成交后持仓，形成只追加复盘证据。

## 3. 复盘口径

每次调仓必须比较三层数据：

1. **TB4 原始目标**：确认信号实现没有变化；
2. **V3 3 倍目标**：确认风险投影准确；
3. **真实成交后持仓**：确认交易所执行与目标一致。

成本归因至少拆分为信号到提交的价格变化、成交滑点、真实手续费、Funding、数量取整和最低
名义金额导致的空仓。权益层面应优先比较：

- 实盘收益与 `3 × TB4` 理论收益的差；
- 真实成交后持仓与 V3 可执行目标的差；
- 原始 TB4 paper 仅作为未放大研究基准，不作为同风险执行基准。

当前系统已展示原始 TB4、3 倍目标和真实持仓的逐币对比；“风险调整后的 3 倍理论权益曲线”
尚未独立落账，属于后续复盘增强项，不能用未放大的 paper 差额替代。

## 4. 规模调整与停止

- 每满 **3 个日历月**才允许评估规模，不因短期盈利提前加钱。
- 只有持仓跟踪误差和成本偏差可解释、当前未处于停止状态时，才允许另发新协议讨论规模变化。
- 实盘或 paper 从各自高点回撤达到 **30%**、出现无法解释的系统性偏离、数据完整性事故或
  风险配置漂移时，停止新增订单并书面复盘。

重要实现边界：当前 30% 机制会**停止后续自动下单**，不会自动发送平仓单。已有仓位仍会继续
承担市场风险，必须由管理员根据急停/平仓操作规程处理。在自动减仓或自动平仓能力正式设计、
测试和审计前，不得把 30% 称为硬性最大损失。

## 5. 参数与修订纪律

- TB4 的市场集合、lookback、vol 窗口、再平衡周期、成本假设均保持冻结。
- V3 的 `3.0` 倍数、逐仓、3x 初始杠杆也被冻结，不提供页面调节旋钮。
- 修改任何上述值必须发布新协议、使旧授权失效并重新预检，不允许边运行边改。
