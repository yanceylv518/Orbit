## 1. 目的与最终判断标准

PAGE-1 已经确定每页应该表达什么；PAGE-2 只解决“如何让用户一眼看懂”。当前页面像一份不断向下追加的长文档，本设计把它改成七个使用同一骨架的驾驶舱。

最终判断标准只有三条：

1. 用户进入任一一级页，10 秒内能说出“现在正常吗、是否要处理、下一步去哪里”。
2. 正常状态一屏看完；异常状态只展开与异常有关的证据，不把审计字段永久堆在页面上。
3. 不了解量化的人看完策略详情，能向别人复述趋势策略如何从 K 线得到仓位、如何调仓、何时停止。

本设计不改变 PAGE-1 的事实、状态语言、权限和安全护栏，不改变 TB4 冻结定义、Paper/LIVE 账本或交易行为。

## 2. 最新范围裁决

新增要求按提出时间覆盖早期冲突项，形成以下边界：

| 内容 | PAGE-2 是否实施 | 数据/命令边界 |
|---|---|---|
| 七页统一布局、视觉层级、收纳方式 | 是 | 纯展示层 |
| 策略目录 → 策略详情 | 是 | 复用现有策略只读数据 |
| 实盘实例列表 → 实例详情 | 是 | 复用现有 LIVE/Paper 读模型 |
| 策略运转五步说明 | 是 | 冻结定义的静态人话投影，不计算新事实 |
| 逐币“为什么多/空/空仓” | PAGE-2 预留位置，SC-3 接入后显示 | 必须来自 runner 同源只读诊断，禁止前端重算 |
| 极简启用向导 | 设计最终形态；命令接入后启用 | 需要自动编排入口，禁止用旧手工步骤冒充 |
| 动态建议最低金额 | 设计展示位置；读模型接入后显示 | 执行层计算，不能写进策略定义 |
| R0 六类结果图 | PAGE-2 定义布局；现有字段可画四类 | 成本瀑布与事件分布需报告契约补充，禁止浏览器反推 |

因此 PAGE-2 页面施工不得夹带新的交易逻辑。SC-3 和启用编排可以紧随 PAGE-2 实施，但必须独立提交、独立测试、独立验收。

## 3. 全站唯一骨架

### 3.1 三段式页面结构

七个一级页只允许使用以下顺序：

1. **答案区**：问题式标题、一句话答案、四格健康/KPI 条、唯一主卡。
2. **操作区**：仅在确有写动作时出现，与观察区有明确边框和底色；只读刷新不算写动作。
3. **明细区**：最多三个可见分组，其余进入 Tab、抽屉或折叠区。

桌面通用线框：

```text
┌─ 页面名 / 问题式标题 ───────────────────────────────────────────────┐
│ 一句话答案                                      [术语帮助] [全局风控] │
├────────────┬────────────┬────────────┬────────────┤
│ 健康/KPI 1 │ 健康/KPI 2 │ 健康/KPI 3 │ 健康/KPI 4 │
├──────────────────────────────────┬───────────────────┤
│ 主卡：回答本页核心问题（约 2/3）  │ 状态/下一步（约 1/3）│
│                                  │ 快捷入口            │
├──────────────────────────────────┴───────────────────┤
│ 写操作区（没有写动作时整段不渲染）                    │
├──────────────────────────────────────────────────────┤
│ [当前] [历史/证据] [审计]   明细区（一次只显示一个 Tab）│
└──────────────────────────────────────────────────────┘
```

390×844 通用线框：

```text
┌─ 页面名 ─────────────┐
│ 问题式标题            │
│ 一句话答案            │
├─────────┬───────────┤
│ KPI 1   │ KPI 2     │
├─────────┼───────────┤
│ KPI 3   │ KPI 4     │
├─────────────────────┤
│ 唯一主卡              │
├─────────────────────┤
│ 状态 / 下一步         │
├─────────────────────┤
│ 写操作（如有）        │
├─────────────────────┤
│ 横向 Tab              │
│ 当前 Tab 内容         │
└─────────────────────┘
```

窄屏不把核心信息藏进汉堡菜单；宽表在自身容器横向滚动，页面本身不得横向溢出。

### 3.2 信息预算

- 首屏全宽面板最多两个：答案区主卡算一个，异常横幅算一个。
- 首屏 KPI 固定四格；窄屏为 2×2，不扩成四个纵向大卡。
- 一级页可见主动作最多两个；危险动作不得与普通动作并排伪装同权重。
- 一级页首屏外最多三个可见分组。
- 正常状态不渲染 run ID、批次号、PID、hash、账本内部状态、原始回执和内部枚举。
- 技术字段统一进入“审计明细”折叠区；异常发生时，只自动展开对应异常证据。

### 3.3 视觉层级

| 层级 | 用途 | 样式纪律 |
|---|---|---|
| L1 | 一句话答案、风险停止 | 24–32px；只能有一个主结论；风险红色不可弱化 |
| L2 | 主数字、实例/策略名称 | 18–24px；同层卡片等高 |
| L3 | 状态与解释 | 13–15px；人话在前，术语在帮助中 |
| L4 | 来源、口径、时间 | 11–12px；低对比但仍满足可读性 |

图表不使用红绿作为唯一编码；线条直接标注名称，避免用户来回对图例。金额、收益率、回撤和权重必须标单位与分母。

### 3.4 列表 → 详情

- `#strategy` 只展示策略目录；详情使用不可变 `definition_id`：`#strategy/{definition_id}`。
- `#forward` 只展示运行实例；详情使用不可变 `instance_id`：`#forward/{instance_id}`。
- `#review` 与 `#risk` 是全局聚合，实例明细通过同一个 `instance_id` 下钻。
- 返回一级页必须保留原筛选与滚动位置。
- 当前只有一个策略或实例，也必须保持列表结构，禁止为 TB4 建一次性特例页面。

├──────────────────────────────────┬───────────────────┤

├──────────────────────────────────┴───────────────────┤

- 主体只出现一套现役数据，名称使用“全市场历史数据”。

- 内容指纹、分区数、缓存文件数只进入技术详情。

## 5. 研究页 `#research`

核心答案：**当前假设是否得到稳定证据，以及正在验证什么。**

桌面：

```text
┌─ 量价关系真的存在吗？ ─────────────────────────────────────────────┐
│ 路径诊断补遗已登记；正式训练等待按 v2.1 重新运行                     │
├────────────┬────────────┬────────────┬────────────┤
│ 正式假设   │ 运行实验   │ 得到支持   │ 未支持/不足 │
├──────────────────────────────────┬───────────────────┤
│ 主卡：当前研究主题 / 当前 R0 结论 │ 下一步              │
│ 两个策略族分列，不混任务与结论    │ 锁箱状态 / 数据绑定  │
├──────────────────────────────────┴───────────────────┤
│ 操作区：仅活动训练显示停止；冻结规则无参数入口         │
├──────────────────────────────────────────────────────┤
│ [当前证据] [组合结果] [历史研究档案]                   │
└──────────────────────────────────────────────────────┘
```

窄屏：R0 总结先出现；两个策略族用两行结论卡；16 组结果放横向表或逐行抽屉，不在首屏铺开。

关键裁决：

- 只有当前有效契约生成的 `TRAINING_FAIL` 才显示为研究结论“未通过训练门槛”，不能显示“任务失败”。已被诊断补遗作废的旧训练只进入审计记录，不作为主卡结论。
- 训练报告存在且两个族都未通过时，锁箱按钮完全不渲染。
- 组合统计、bootstrap 区间、诊断切片进入“组合结果”；主卡只讲结论及原因。
- M0/F1/G1/G2 进入“历史研究档案”，不与当前主题并列。

### 5.1 R0 结果图形化工作区

“当前证据”默认显示结论和最接近门槛的组合；“组合结果”使用八个固定视图，不把参数或事件图纵向堆叠：

```text
┌─ 为什么通过 / 为什么失败？ ───────────────────────────────────────┐
│ [组合] [成本] [层级] [分年] [诊断] [收益] [路径散点] [路径分布]     │
├──────────────────────────────────┬───────────────────┤
│ 当前 Tab 主图（约 2/3）           │ 人话结论（约 1/3） │
│ 轴、单位、零线、区间直接标注       │ 失败门 / 下一版启示 │
└──────────────────────────────────┴───────────────────┘
```

八类图的固定表达：

| Tab | 图形 | 必须回答 | 当前 V2 训练报告 |
|---|---|---|---|
| 组合总览 | 16 组均值点 + bootstrap 区间须线；零线直标 | 哪组接近门槛、差多少 | 已具备 |
| 成本拆分 | 毛收益 → Funding → 手续费/滑点 → 净收益瀑布 | 信号无效，还是被成本吃掉 | **缺字段** |
| 市场层级 | 高/中/低流动性并排点图 | 利润来自哪类市场 | 已具备 |
| 分年 | 年度均值点线；正负零线直标 | 是否只靠某一年 | 已具备 |
| 诊断 | 量递增/非递增、新上市/成熟两组并排 | 两个用户直觉是否成立 | 已具备 |
| 收益分布 | 单事件净收益直方图 + 中位数/尾部标注 | 稳定小赚还是极端事件撑起 | **缺字段** |
| 路径散点 | 每事件最大浮盈（MFE）对最大浮亏（MAE），百分比/ATR 可切换 | 是否存在适合人工筛选的高盈亏比空间 | **待 R0-DIAG v2.1** |
| 路径分布 | MFE、MAE 与各自到达时间的分布；H 与 2×H 分列 | 固定退出/止损是否过早 | **待 R0-DIAG v2.1** |

成本拆分和收益分布登记为 `R0-VIS REPORT GAP`；路径散点和路径分布由 `R0-DIAG v2.1` 提供。新增字段只增加测量，不得改变冻结门、选参或判定；不得从均值、置信区间反推，也不得用作修改本版参数的入口。字段未接入时对应 Tab 显示“报告尚未记录这一层证据”。

图只用于解释本版死因/活因并设计下一版预注册，不出现“按图调参”“重新用更好参数运行”等动作。

### 6.2 策略详情 `#strategy/{definition_id}`

核心答案：**这个策略怎么运转、凭什么被允许、最坏会怎样。**

桌面：

```text
┌─ 趋势策略 ─────────────────────────────────────────────────────────┐
│ 跟随多个时间尺度的共同方向，每周按风险重新分配仓位                  │
├──────────────────────────────────────────────────────┤
│ 它是怎么运转的（横向五步）                            │
│ 4h收盘 → 五尺度投票 → 波动缩放 → 每7天调仓 → 警戒线停止│
├──────────────────────────────────┬───────────────────┤
│ 主卡：当前准入与证据摘要           │ 风险边界            │
│ 历史考试 / 模拟期 / 当前版本       │ ×3实例投影 / 30%停止│
├──────────────────────────────────┴───────────────────┤
│ [运转说明] [证据] [风险与版本] [审计明细]             │
└──────────────────────────────────────────────────────┘
```

窄屏五步改为纵向步骤条：

```text
① 每 4 小时收一次盘
│ 只用已经结束的 K 线，不偷看未来
② 五个时间尺度分别投票
│ 最近在涨、在跌，还是没有共同方向
③ 按波动大小计算比例
│ 波动大的币少拿，波动小的币多拿
④ 每 7 天自动调一次仓
│ 周内只执行保护，不反复追涨杀跌
⑤ 亏到警戒线停止新单
   真钱实例使用 ×3 投影；组合回撤 30% 停止
```

“×3”和金额只描述运行实例如何投影策略比例，绝不写入策略定义。策略层只展示目标波动、比例权重、仓位上限和回撤规则。

```text

│ 金额   [自由输入              USDT]│
│ 建议最低金额：动态计算；低于时说明 │
│ “只能执行部分组合”，不伪装为禁用  │
│ 确认语 [________________________] │
│                 [取消] [确认启动] │
└───────────────────────────────────┘
```

点击后由后端自动完成基准初始化、规则刷新、账户模式、杠杆保证金和全部预检。页面只显示自动步骤进度与失败原因，不要求用户逐项操作。编排接口未交付前，“确认启动”不得接到旧的多按钮流程。

金额属于实例绑定；运行中改金额使用独立“变更风险金额”流程、确认语和审计版本，详情页不提供随手输入框。

## 11. 交互与状态规则

### 11.1 Tab、抽屉与折叠

- Tab 表示同一页面的互斥观察角度；切换不触发业务写入。
- 抽屉用于单条详情和一次性流程，关闭后回到原上下文。
- 折叠仅用于审计/技术内容；风险异常不能默认折叠。
- URL 记录一级/详情路由；临时抽屉状态不制造不可维护的路由。

### 11.2 加载、空、错、无权

- 首次加载使用等高骨架，禁止先渲染 0 再跳真实值。
- 空状态必须同时说明原因、下一步和不受影响的部分。
- 区块错误只占该区块；全页只在身份失效或核心事实源不可用时失败。
- `403` 明确显示无权，不伪装为空。
- 自动刷新不得让卡片高度抖动或把用户打开的抽屉关闭。

### 11.3 异常驱动

| 异常 | 自动展开 |
|---|---|
| 数据不完整 | 数据页“覆盖与质量”的相关缺口 |
| 研究任务程序错误 | 研究页任务错误，不展开统计结论 |
| 执行完成但有异常 | 实例详情“本周执行对了吗” |
| 接近/触发停止线 | 实例详情风险问答 + 风控页对应实例 |
| 账户同步异常 | 账户页对应账户 + 实盘实例健康问答 |

## 12. 组件与样式落地

新增或收敛为以下通用展示组件，避免七页各造一套：

- `PageAnswerHeader`：问题、答案、更新时间、全局入口。
- `KpiStrip`：固定四格，桌面 4×1、窄屏 2×2。
- `PrimaryCardLayout`：2/3 主卡 + 1/3 侧卡。
- `ActionZone`：写操作隔离区。
- `DetailTabs`：统一 Tab 与窄屏滚动行为。
- `EntityList`：策略、实例、账户统一列表骨架。
- `AuditDisclosure`：默认关闭的审计明细。
- `ExceptionRow`：异常时展开证据与下一步。
- `StrategyLifecycleSteps`：策略运转五步，桌面横向、窄屏纵向。
- `ResearchEvidenceTabs`：R0 八类证据视图，一次只渲染一图。
- `IntervalDotPlot`、`WaterfallChart`、`GroupedEvidencePlot`、`EventHistogram`：共享坐标、零线、直接标注与无障碍配色规则。
- `MfeMaeScatterPlot`、`PathDistributionPlot`：支持百分比/ATR 双口径及 H/2×H 对照，禁止默认裁掉尾部事件。

现有 `StatusBadge`、`HelpTip`、图表组件继续复用。不得以复制 CSS 的方式为每页造同义卡片。

## 13. 分批实施与提交边界

设计冻结后按以下顺序实施，每批均须独立提交、推送、验收：

1. **骨架层**：通用组件、布局 token、路由解析；不迁移业务内容。
2. **批一**：实盘一级/实例详情 + 数据页。日常最高频，先验证信息预算。
3. **批二**：研究 + 复盘 + 风控。
4. **批三**：策略目录/详情 + 账户。
5. **SC-3**：接入逐币持仓原因，只读、同源、禁止前端重算。
6. **启用编排**：三项选择 + 一次确认；自动执行既有护栏步骤。

如果要求“一次装修完成”，上述批次仍保留为内部可回滚提交，但在七页全部通过验收前不宣告 PAGE-2 完成。

## 14. 验收清单

### 14.1 每页

- 第一视口只有一句答案和一张主卡，没有第三个全宽面板。
- 桌面充分使用横向空间；窄屏无页面级横向溢出。
- 首屏外最多三个可见分组。
- 正常状态一屏回答核心问题；异常只展开相关细节。
- 数字有单位、来源或截止时间。
- 任务、数据、研究、准入、运行和执行状态没有混用。

### 14.2 结构

- 策略和实盘均为列表 → 详情，不存在单策略整页硬编码。
- 数据页只有一套现役数据；旧数据只在证据封存中。
- 实盘一级页只有总结、四格健康、实例列表、异常提示。
- 审计字段正常状态不渲染。
- 策略详情五步说明可被非量化用户准确复述。

### 14.3 安全与回归

- PAGE-1 内容、状态语言、权限和确认机制保持不变。
- 未接入的 SC-3/动态最低金额不在前端计算或伪造。
- 急停、30% 停止和完整性风险语言不软化。
- `verify_modular_baseline.py` 每批通过。
- 后端全量测试、前端 check/build、`git diff --check` 通过。
- 七个一级页及策略/实例详情均完成桌面和 390×844 真实浏览器验收。
- TB4 受保护文件 hash 零变化；LIVE/Paper 运行账本零迁移。
