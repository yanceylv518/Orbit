# SIG-1 信号服务最小可用版

状态：已冻结实现规格
日期：2026-08-14

> 历史口径说明：RC-0B 的 29,311 条突破与 9,183 条超跌，是在 R-0“持仓期内不重复取同参数信号”的研究事件母池中得到的工作量与门槛参考。SIG-1 不把这层研究去重当成隐藏筛选条件；运行时逐根检查每一根已收盘 15 分钟 K 线，并允许每个信号建立独立、可重叠的模拟单。因此验收会复现 RC-0B 参考池的范围和 p90 门槛，但不会把参考池条数冒充实时逐根扫描的总条数。

## 目标与边界

SIG-1 只负责四件事：扫描冻结形态、为每个信号建立虚拟交易、保护人工工作量、把极少数高趋势强度信号即时发到 Pushover。它不读取账户、持仓或金额，不下真实订单，也不改动 TB4 运行目录。

真实运行需要部署到能够访问 Binance USDⓈ-M Futures 公共接口的主机。当前代码和回放测试可以本地完成，但没有服务器部署就不会产生实时信号。

## 冻结信号范围

币池在每根 15 分钟 K 线收盘时判断：取此前 3 个完整 UTC 日的日成交额，其中位数必须不低于 2 亿 USDT；同时合格市场少于 3 个时整批不产生信号。

- 突破族：收盘价突破此前 32 根 K 线最高/最低价，当前 K 线成交额至少为此前 96 根中位成交额的 4 倍，多空对称。
- 超跌族：相对 16 根前收盘价下跌至少 10%，当前收盘高于前一根收盘且不低于当前开盘，仅做多信号。
- 所有输入只含已经收盘的 K 线。信号身份由信号族、币种、收盘时刻和方向确定，重启后不会重复入账。

冻结配置位于 `config/signals/sig1.v1.json`，并绑定 RC-0B 正式报告 SHA-256。

## 虚拟交易账

每个信号都会先写 `SIGNAL_DETECTED`，随后写 `SIM_TRADE_PLANNED`，与是否进入每日 30 条候选、是否推送、推送是否成功无关。

- 次根开盘建立虚拟交易；
- 初始止损距离为 `2 × ATR14`；
- 最多持有 32 根 15 分钟 K 线，在其后的开盘价退出；
- 跳空越过止损时按更差的开盘价退出；
- 同一根同时触及止损和时间退出时止损优先；
- 每个信号独立记账，允许虚拟交易重叠。

账本使用不可变 manifest 和 JSONL SHA-256 哈希链。启动时会从头验证序号、前序哈希和记录哈希；任何历史修改都会 fail-closed。

## 两种限额不要混淆

每日 30 条是人工页面工作量保护。系统按 96 根方向对齐趋势强度降序计算当日候选，前 30 条进入候选范围；被截断的信号仍完整保留并继续模拟。

Pushover 是另一条更窄的即时旁路：

- 突破族趋势强度门槛 `9.94136807817591`；
- 超跌族趋势强度门槛 `1.4637837227420296`；
- 两个值分别是冻结 SIG-1 训练范围内的同族 p90，按 `(样本数-1)×0.90` 位置线性插值；
- 达标即推，不等待日终排序；
- 每个信号日最多成功推送 3 条；失败最多尝试 3 次，超过 30 分钟不再补推。

推送消息只含币种、方向、形态原因、趋势强度、参考进场/止损/1R/2R/3R 和信号时间，不含账户信息。

## 凭证与故障隔离

配置中只允许 `env:`、`dpapi:` 或 `aesgcm:` 引用。默认使用：

- `env:ORBIT_PUSHOVER_API_TOKEN`
- `env:ORBIT_PUSHOVER_USER_KEY`

发送前才通过现有 CredentialVault 解引用。返回值、服务状态、账本和异常记录均不保存 Token 或 User Key。Pushover 网络或凭证失败只追加 `PUSH_FAILED`，不能回滚或阻止信号与虚拟交易落盘。

## 启动

单次扫描：

```powershell
cd backend
python tools/run_sig1_signal_service.py
```

服务器常驻扫描：

```powershell
cd backend
python tools/run_sig1_signal_service.py --loop
```

默认账本目录为 `var/signals/sig1`。部署前必须配置凭证引用并确认主机可访问 Binance 与 Pushover；SIG-2 才会增加页面和人工成交配对。
